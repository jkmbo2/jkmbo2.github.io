## 从一个问题开始

有时候，学习结束后最难回答的问题，是「我究竟理解了什么」。视频看过了，代码也运行成功了，但换一个例子，又不知道从哪里开始。

这份博客想保留下来的，是从问题到理解之间的过程。

不需要一开始就写成教程。一个还没解决的问题、一段终于跑通的代码、一次发现自己理解有误的瞬间，都可以成为一篇笔记的起点。

## 一篇笔记的四个部分

### 1. 把问题写具体

「学习 Python」很宽泛，而「为什么修改一个列表会影响另一个变量」就具体得多。问题越具体，越容易设计一个小实验。

### 2. 留下尝试的过程

记下你尝试了什么、预期会发生什么，以及实际看到的结果。不只保存最终能运行的代码，也说明之前为什么没有成功。

### 3. 用自己的话解释

尝试离开原文，重新解释这个概念。能不能举一个更小的例子？能不能说清楚它适用于什么情况，又有哪些边界？

### 4. 留一个下一步

下一步不需要很大。换一组输入、改一个条件、补一张图，都是很好的继续方式。

## 让笔记彼此连接

单篇记录可以很小。通过分类、标签和文章之间的链接，它们会慢慢形成一张网。

| 记录类型 | 可以从哪里开始 | 希望留下什么 |
| --- | --- | --- |
| 技术实践 | 一个能复现的问题 | 代码、结果与解释 |
| 阅读思考 | 一段让你停下来的内容 | 观点、联系与疑问 |
| 学习复盘 | 一周的尝试 | 有效的方法与下一步 |

比起收集所有信息，更值得关注的是：这篇记录能否帮助未来的自己更快地重新理解。

## 开始你自己的第一篇

这个博客的文章使用 Markdown 文件保存。你可以创建一份草稿：

```bash
npx hexo new post "我的第一篇学习笔记"
```

然后在 `source/_posts/我的第一篇学习笔记.md` 中写作，用 `npm run dev` 预览。确认内容后，将文章放在 `source/_posts/` 目录中，再构建并发布。

> 每篇文章不必回答所有问题。但每次记录，都可以让理解向前走一点。
